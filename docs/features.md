# Symbio Feature List

> AI Infra 级别的多 Agent 协同框架，聚焦解耦、高可用和可扩展性。
> 从"多 Agent 调度工具"升维为"具备自我进化能力、能在复杂/隔离环境中稳定运行的 AI 基础设施"。

---

## 0. 杀手级亮点 (Killer Features)

> 与同类开源竞品拉开代差的核心特性。

### 0.1 极致离线与私有化环境存活能力 (Air-gapped & Local-First)
> 很多企业级生产环境完全隔离外网，我们原生支持"无网环境"。

- [ ] 本地大模型平滑降级 — 检测外部 API 不可用时，无缝切换到本地局域网开源模型 (vLLM / Ollama)
- [ ] 全本地依赖闭环 — 记忆系统、工具链、调度引擎在无外网状态下完整运作
- [ ] 企业内网零改造部署 — 本地调试 → 内网生产环境一键平推

### 0.2 高质量数据集自动反哺机制 (Data Flywheel)
> 系统不仅在"做任务"，还在"沉淀数据资产"。

- [ ] 轨迹捕获 — 自动记录多 Agent 协同解决任务的完整链路 (Thought → Action → Observation → Result)
- [ ] 微调数据导出 — 自动清洗并格式化为标准数据集 (ShareGPT / Alpaca 格式)
- [ ] 越跑越值钱 — 系统运行越多，沉淀的高质量语料资产越丰富

### 0.3 细粒度主动可观测性 (Agentic Observability)
> 多 Agent 协同最大痛点是"黑盒化"，我们让一切透明。

- [ ] 时空运行轨迹图 — 类似分布式链路追踪 (Trace) 的可视化状态，谁派发、谁等待、谁 Token 异常，一目了然
- [ ] 记忆快照回放 — 在任务失败节点"打断点"，恢复当时记忆状态，方便复现调试
- [ ] Token 消耗热力图 — 可视化各 Agent/工具的 Token 消耗分布

### 0.4 动态人类介入总线 (Human-in-the-Loop, HITL)
> 在自动化和安全性之间找到完美平衡。

- [ ] 高危动作悬挂 — SubAgent 执行高危操作（生产数据库修改、批量删除、大额 API 调用）时自动挂起
- [ ] IM 异步授权 — 通过微信/飞书向管理员发送授权卡片，手机点击"同意"或回复修改意见后继续执行
- [ ] 审批超时策略 — 超时自动拒绝/降级执行/转交其他管理员

### 0.5 MCP (Model Context Protocol) 原生支持
> 不自己造所有轮子，原生兼容最前沿的 MCP 协议。

- [ ] 标准化工具挂载 — 任何人写的标准 MCP 工具集，零配置直接挂载让所有 SubAgent 调用
- [ ] 工具生态接入 — 天气、数据库、云资源、第三方 API 等 MCP 工具即插即用
- [ ] 社区工具市场 (远期) — 共享与分发 MCP 工具集

### 0.6 并发流控与分布式速率限制 (LLM Rate Limiting & Concurrency Control)
> 多 Agent 系统最容易崩溃的不是代码，而是大模型 API。

- [ ] 令牌桶/漏桶算法网关 — 在 ModelRouter 层原生内置针对不同模型供应商的异步流控器
- [ ] 动态退避与抖动重试 (Exponential Backoff with Jitter) — 遇到 429 时智能等待错峰重试，确保长作业存活率
- [ ] RPM/TPM 预估与预检 — 派发 SubAgent 前预估总消耗，避免瞬间打爆限额

### 0.7 任务级"金融预算"与步数熔断 (Task Budgeting & Guardrails)
> Agent 自主性是双刃剑，可能死循环烧光 API 额度。

- [ ] 硬性预算熔断 (Cost Cap) — 用户提交任务时可指定 max_cost_usd，超过阈值立刻挂起并通知
- [ ] 最大步数限制 (Max Steps Guard) — 限制单次任务最大循环轮次（如 30 轮），防止逻辑死循环
- [ ] 实时成本仪表盘 — 可视化当前任务链的 Token 消耗和预估费用

### 0.8 从"黑名单"到"绝对沙箱"的安全平替 (Strict Sandbox Evolution)
> 黑名单防不住恶意或意外，需要物理隔离。

- [ ] 容器化/微型虚拟机隔离 — ShellTool 和 FileTool 原生支持运行在 Docker 容器或轻量级沙箱 (E2B, WASM)
- [ ] 显式高危权限分级 — 工具划分为 Read-Only（安全）、Write（敏感）、Execute（高危），高危强制绑定 HITL
- [ ] 最小权限原则 — Agent 默认只拥有完成任务所需的最小权限集

### 0.9 运行时状态持久化与断点续传 (State Persistence & Hydration)
> 复杂任务可能耗时数小时，中途断网/重启不能丢失进度。

- [ ] 图状态检查点 (Graph Checkpointing) — 在关键节点将任务 DAG 状态、短期记忆、执行日志序列化到 SQLite
- [ ] 断点唤醒 (Hydration) — 系统重启后一键恢复到崩溃前状态继续执行
- [ ] 手动快照 — 用户可主动保存当前执行状态，用于回滚或复用

### 0.10 自动化评测管道 (Agentic CI/CD & Eval Pipeline)
> 改了 A 处 Prompt，B 处 Agent 不能莫名变蠢。

- [ ] symbio eval 模块 — 编写测试集（输入任务 → 预期工具调用 → 预期输出）
- [ ] 合并前自动评测 — 代码合并或发布前自动评估模型路由、意图识别、工具调用准确率
- [ ] 回归检测 — 确保系统进化是正向的，而非退化

### 0.11 动态拓扑自适应与运行时重规划 (Dynamic DAG & Runtime Re-planning)
> 市面框架都是静态图，我们实现"兵无常势，水无常形"。

- [ ] 完全动态 DAG — 放弃预设路径，Orchestrator 只生成初始宏观步骤
- [ ] 运行时拓扑重构 — SubAgent 返回超预期结果时，动态增删节点、合并并行链路、分支切换
- [ ] 自适应执行 — 根据中间观测结果实时调整后续策略，而非机械执行预设流程

### 0.12 上下文智能剪枝与 Prompt Cache 深度对齐 (Context Pruning & Cache Alignment)
> 长作业上下文膨胀导致费用飙升、注意力涣散，我们从底层工程优化。

- [ ] 语义剪枝 — 通过小模型或规则自动提取历史中的"决策关键点"和"状态增量"，裁剪无用中间体（原始 HTML、编译日志等）
- [ ] 缓存对齐布局 — 严格按 Claude 等模型的缓存前缀匹配规则设计短期记忆内存块布局
- [ ] 成本优化 — 确保长对话中 90%+ 静态前缀持续命中 Cache，斩断 50%+ 输入成本，卡死首字延迟 (TTFT)

### 0.13 多代理共识辩论与交叉验证 (Multi-Agent Debate & Cross-Verification)
> 高精度任务用"算力换确定性"，消灭幻觉。

- [ ] 三家分晋机制 — 高危/极高复杂度任务自动克隆 3 个 SubAgent（Proposer 创造者、Critic 批判者、Refiner 修正者）
- [ ] 多轮内生辩论 — 针对中间结果进行多轮辩论，直到达成共识或投票决定最终输出
- [ ] 交叉验证 — 不同系统提示词的 Agent 互相校验，用多样性消灭盲区

### 0.14 从向量到本体：长效记忆的本体化 (Ontology-Enhanced Memory)
> 向量检索只能找相似片段，本体(Ontology)理解领域概念层次与推理规则。

- [ ] Vector + Ontology 双驱动 — 长期记忆演进为向量+本体混合架构
- [ ] 概念层次定义 — 定义领域内的类(Class)、属性(Property)、关系(Relation)、约束(Constraint)
- [ ] 语义推理 — 基于本体推理规则自动推导隐含知识（如：A 依赖 B，B 依赖 C → A 间接依赖 C）
- [ ] 全景语义网 — 检索时通过本体关联把破碎向量片段编织成语义网络，赋予 Agent "常识常理联想能力"

## 1. 核心骨架与运行时 (Core Foundation)

> 系统的地基，决定稳定性和调度能力。

### 1.1 模型路由引擎 (Model Router)
- [ ] 多模型统一接口封装 (Anthropic, OpenAI, 本地开源模型等)
- [ ] 动态复杂度路由策略 (Haiku → Sonnet → Opus/GPT-4)
- [ ] Token 消耗追踪与熔断机制

### 1.2 状态与生命周期管理
- [ ] Agent 运行状态机 (Idle, Running, Waiting, Paused, Failed)
- [ ] 任务中断与恢复机制

### 1.3 基础通信总线 (Event Bus)
- [ ] 统一日志系统 (Console + File，支持级别过滤)
- [ ] 核心配置管理 (YAML/TOML + 环境变量加载)

---

## 2. 多 Agent 协同编排 (Multi-Agent Orchestration)

> 区别于单体应用的护城河。

### 2.1 分层 Agent 架构
- [ ] BaseAgent 抽象基类
- [ ] 主 Agent (Orchestrator) 意图识别与任务拆解
- [ ] SubAgent (Worker) 动态生成与派发

### 2.2 协同机制
- [ ] SubAgent 之间的上下文隔离与关键信息共享
- [ ] 任务执行回调与结果聚拢 (Map-Reduce 模式)

### 2.3 错误隔离与自愈
- [ ] 单个 SubAgent 崩溃不影响全局
- [ ] 自动重试与 fallback 策略

---

## 3. 记忆中枢 (Memory System)

> 基于 LanceDB 的高性能、多模态上下文管理。

### 3.1 短期记忆 (Short-term)
- [ ] 基于滑动窗口的会话上下文管理
- [ ] 自动总结 (Summary) 机制，防止上下文超载

### 3.2 长期记忆 (Long-term)
- [ ] LanceDB 向量数据库集成与初始化
- [ ] 文档、代码、历史对话的 Embedding 与持久化
- [ ] 混合检索机制 (Semantic Search + Keyword)

### 3.3 记忆内化与遗忘
- [ ] 相似记忆去重与合并
- [ ] 过期低优记忆的修剪机制

## 开发原则

**大处着眼，小处着手。**

严格按敏捷模式，优先级排序：

1. **P0** — 核心骨架 (配置 + 日志 + 大模型接口调用)
2. **P0** — 跑通第一个 SubAgent 派发
3. **P0** — 并发流控 + 预算熔断 (防御性设计，上线必备)
4. **P1** — LanceDB 记忆系统 + 语义剪枝
5. **P1** — 工具接入 + MCP 支持
6. **P1** — 安全沙箱 (容器化隔离)
7. **P1** — 本地模型降级 (离线能力)
8. **P1** — 状态持久化与断点续传
9. **P1** — 动态 DAG 与运行时重规划
10. **P2** — IM 接入 + HITL 人类介入
11. **P2** — 可观测性 (Trace / 回放)
12. **P2** — 进化引擎 + 数据飞轮
13. **P2** — Prompt Cache 深度对齐
14. **P2** — 自动化评测管道
15. **P2** — 多代理共识辩论
16. **P3** — 本体记忆引擎 (Ontology-Enhanced Memory)
17. **P3** — Web UI / Desktop 客户端
18. **P3** — 定时任务 / 事件驱动

> 只要基础总线通了，后面的都是在树干上长树枝。

## 项目定位

**Symbio 不是一个套壳玩具，而是一个真正的 AI Infra 级多 Agent 协同框架。**

核心差异化：
- **解耦** — 模块独立，可替换可插拔
- **高可用** — 错误隔离、自愈、离线降级、断点续传
- **安全** — 绝对沙箱、预算熔断、HITL 人类介入
- **智能** — 动态 DAG、语义剪枝、共识辩论、本体推理
- **可扩展** — 插件化、MCP 兼容、工具生态开放
- **自进化** — 数据飞轮、记忆内化、策略优化、评测管道
