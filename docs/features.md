# Symbio Feature List

> AI Infra 级别的多 Agent 协同框架，聚焦解耦、高可用和可扩展性。
> 从"多 Agent 调度工具"升维为"具备自我进化能力、能在复杂/隔离环境中稳定运行的 AI 基础设施"。

---

## 0. 杀手级亮点 (Killer Features)

> 与同类开源竞品拉开代差的核心特性。

### 0.1 极致离线与私有化环境存活能力 (Air-gapped & Local-First)
> 很多企业级生产环境完全隔离外网，我们原生支持"无网环境"。

- [ ] 本地大模型平滑降级 — 检测外部 API 不可用时，无缝切换到本地局域网开源模型 (vLLM / Ollama)
- [ ] 全本地依赖闭环 — 记忆系统、工具链、调度引擎在无外网状态下完整运作
- [ ] 企业内网零改造部署 — 本地调试 → 内网生产环境一键平推

### 0.2 高质量数据集自动反哺机制 (Data Flywheel)
> 系统不仅在"做任务"，还在"沉淀数据资产"。

- [ ] 轨迹捕获 — 自动记录多 Agent 协同解决任务的完整链路 (Thought → Action → Observation → Result)
- [ ] 微调数据导出 — 自动清洗并格式化为标准数据集 (ShareGPT / Alpaca 格式)
- [ ] 越跑越值钱 — 系统运行越多，沉淀的高质量语料资产越丰富

### 0.3 细粒度主动可观测性 (Agentic Observability)
> 多 Agent 协同最大痛点是"黑盒化"，我们让一切透明。

- [ ] 时空运行轨迹图 — 类似分布式链路追踪 (Trace) 的可视化状态，谁派发、谁等待、谁 Token 异常，一目了然
- [ ] 记忆快照回放 — 在任务失败节点"打断点"，恢复当时记忆状态，方便复现调试
- [ ] Token 消耗热力图 — 可视化各 Agent/工具的 Token 消耗分布

### 0.4 动态人类介入总线 (Human-in-the-Loop, HITL)
> 在自动化和安全性之间找到完美平衡。

- [ ] 高危动作悬挂 — SubAgent 执行高危操作（生产数据库修改、批量删除、大额 API 调用）时自动挂起
- [ ] IM 异步授权 — 通过微信/飞书向管理员发送授权卡片，手机点击"同意"或回复修改意见后继续执行
- [ ] 审批超时策略 — 超时自动拒绝/降级执行/转交其他管理员

### 0.5 MCP (Model Context Protocol) 原生支持
> 不自己造所有轮子，原生兼容最前沿的 MCP 协议。

- [ ] 标准化工具挂载 — 任何人写的标准 MCP 工具集，零配置直接挂载让所有 SubAgent 调用
- [ ] 工具生态接入 — 天气、数据库、云资源、第三方 API 等 MCP 工具即插即用
- [ ] 社区工具市场 (远期) — 共享与分发 MCP 工具集

## 1. 核心骨架与运行时 (Core Foundation)

> 系统的地基，决定稳定性和调度能力。

### 1.1 模型路由引擎 (Model Router)
- [ ] 多模型统一接口封装 (Anthropic, OpenAI, 本地开源模型等)
- [ ] 动态复杂度路由策略 (Haiku → Sonnet → Opus/GPT-4)
- [ ] Token 消耗追踪与熔断机制

### 1.2 状态与生命周期管理
- [ ] Agent 运行状态机 (Idle, Running, Waiting, Paused, Failed)
- [ ] 任务中断与恢复机制

### 1.3 基础通信总线 (Event Bus)
- [ ] 统一日志系统 (Console + File，支持级别过滤)
- [ ] 核心配置管理 (YAML/TOML + 环境变量加载)

---

## 2. 多 Agent 协同编排 (Multi-Agent Orchestration)

> 区别于单体应用的护城河。

### 2.1 分层 Agent 架构
- [ ] BaseAgent 抽象基类
- [ ] 主 Agent (Orchestrator) 意图识别与任务拆解
- [ ] SubAgent (Worker) 动态生成与派发

### 2.2 协同机制
- [ ] SubAgent 之间的上下文隔离与关键信息共享
- [ ] 任务执行回调与结果聚拢 (Map-Reduce 模式)

### 2.3 错误隔离与自愈
- [ ] 单个 SubAgent 崩溃不影响全局
- [ ] 自动重试与 fallback 策略

---

## 3. 记忆中枢 (Memory System)

> 基于 LanceDB 的高性能、多模态上下文管理。

### 3.1 短期记忆 (Short-term)
- [ ] 基于滑动窗口的会话上下文管理
- [ ] 自动总结 (Summary) 机制，防止上下文超载

### 3.2 长期记忆 (Long-term)
- [ ] LanceDB 向量数据库集成与初始化
- [ ] 文档、代码、历史对话的 Embedding 与持久化
- [ ] 混合检索机制 (Semantic Search + Keyword)

### 3.3 记忆内化与遗忘
- [ ] 相似记忆去重与合并
- [ ] 过期低优记忆的修剪机制

---

## 4. 工具与环境沙箱 (Tooling & Sandbox)

> 让系统长出手脚，在物理/虚拟环境中做事。

### 4.1 核心工具链
- [ ] 文件系统操作 (读、写、搜索、AST 解析)
- [ ] 终端 Shell 执行 (支持长连接和流式输出)
- [ ] Git 自动化操作模块

### 4.2 安全与隔离
- [ ] 危险命令拦截 (黑名单机制)
- [ ] 依赖包和环境管理的沙箱化支持

---

## 5. 进化引擎 (Evolution & Intelligence)

> 越用越聪明。

### 5.1 反馈回路
- [ ] 用户指令与修正的自动收集
- [ ] 失败任务的自动复盘与 Root Cause 记录

### 5.2 策略优化
- [ ] 提取高频成功路径，固化为系统 Prompt 或 SOP

---

## 6. 接口与多端接入 (Interfaces & Clients)

> 将 Infra 能力暴露给不同终端。

### 6.1 服务端与 API
- [ ] RESTful API / FastAPI 接口层封装
- [ ] WebSocket 支持流式对话与状态推送

### 6.2 IM 平台接入
- [ ] QQ / 微信 (基于相关协议或框架)
- [ ] 飞书 / 钉钉企业级机器人接入

### 6.3 客户端 (规划中)
- [ ] 本地跨平台客户端 (Tauri + Next.js)
- [ ] Web 交互控制台

---

## 7. 定时与事件驱动 (Schedulers & Triggers)

> 全天候 24 小时托管运作。

### 7.1 触发器
- [ ] 基于 Cron 的定时任务
- [ ] Webhook 事件监听 (如代码仓库 Push 触发自动化 Review)

## 开发原则

**大处着眼，小处着手。**

严格按敏捷模式，优先级排序：

1. **P0** — 核心骨架 (配置 + 日志 + 大模型接口调用)
2. **P0** — 跑通第一个 SubAgent 派发
3. **P1** — LanceDB 记忆系统
4. **P1** — 工具接入 + MCP 支持
5. **P1** — 本地模型降级 (离线能力)
6. **P2** — IM 接入 + HITL 人类介入
7. **P2** — 可观测性 (Trace / 回放)
8. **P2** — 进化引擎 + 数据飞轮
9. **P3** — Web UI / Desktop 客户端
10. **P3** — 定时任务 / 事件驱动

> 只要基础总线通了，后面的都是在树干上长树枝。

## 项目定位

**Symbio 不是一个套壳玩具，而是一个真正的 AI Infra 级多 Agent 协同框架。**

核心差异化：
- **解耦** — 模块独立，可替换可插拔
- **高可用** — 错误隔离、自愈、离线降级
- **可扩展** — 插件化、MCP 兼容、工具生态开放
- **自进化** — 数据飞轮、记忆内化、策略优化
