# Symbio UI 设计方案

> 方案先行，设计升维。UI 不是附属品，而是 Symbio 与用户交互的唯一窗口。

---

## 1. 设计哲学

### 1.1 核心理念

**"信息密度优先，操作效率至上"**

- **信息密度** — 在有限的屏幕空间内展示最多有价值的信息
- **操作效率** — 减少点击次数，常用操作一键直达
- **视觉层次** — 用色彩、间距、字重区分信息优先级
- **一致性** — 统一的交互模式，降低学习成本

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| 渐进式复杂度 | 简单场景简单，复杂场景可选 |
| 实时反馈 | 每个操作都有即时视觉反馈 |
| 错误友好 | 错误信息清晰，修复建议明确 |
| 键盘优先 | 支持快捷键，减少鼠标操作 |
| 暗色主题 | 默认暗色，减少视觉疲劳 |

## 3. 核心页面设计

### 3.1 对话页面 (/chat)

**布局：** 三栏布局

```
┌──────────┬────────────────────────────┬──────────┐
│          │                            │          │
│  会话    │      对话内容区域           │  上下文   │
│  列表    │                            │  面板    │
│          │  ┌──────────────────────┐  │          │
│  会话1   │  │ 用户消息             │  │  记忆    │
│  会话2   │  │                      │  │  检索    │
│  会话3   │  │ Agent 回复           │  │  结果    │
│  ...     │  │                      │  │          │
│          │  │ 工具调用             │  │  工具    │
│          │  │                      │  │  执行    │
│          │  └──────────────────────┘  │  日志    │
│          │                            │          │
│          │  ┌──────────────────────┐  │          │
│          │  │ 输入框 + 快捷操作     │  │          │
│          │  └──────────────────────┘  │          │
└──────────┴────────────────────────────┴──────────┘
```

**核心组件：**

| 组件 | 说明 |
|------|------|
| 会话列表 | 左侧栏，显示历史会话，支持搜索、分组、置顶 |
| 消息气泡 | 支持 Markdown、代码高亮、表格、图片 |
| 工具调用卡片 | 折叠式展示工具调用详情（输入/输出/耗时） |
| 上下文面板 | 右侧栏，展示当前会话的记忆检索结果、工具执行日志 |
| 输入框 | 支持多行、@提及工具、附件上传、快捷命令 |
| 快捷操作栏 | 常用操作按钮（清空会话、导出、分享） |

**交互细节：**

- 消息流式输出，实时显示 Token 消耗
- 工具调用支持展开/折叠，显示执行状态（进行中/成功/失败）
- 支持消息重试、编辑、删除
- 支持会话分支（从某条消息重新开始）
- Ctrl+Enter 发送，Shift+Enter 换行

### 3.2 任务监控页面 (/tasks)

**布局：** 双栏布局

```
┌─────────────────────────────────────────────────────────────┐
│                      任务列表 + 过滤器                        │
├────────────────────────────────┬────────────────────────────┤
│                                │                            │
│        DAG 可视化区域           │      任务详情面板           │
│                                │                            │
│    ┌───┐     ┌───┐            │  任务 ID: xxx              │
│    │ A │────▶│ B │            │  状态: 运行中              │
│    └───┘     └───┘            │  模型: claude-sonnet       │
│       │                       │  Token: 1234 / 5000       │
│       ▼                       │  耗时: 2m 30s              │
│    ┌───┐     ┌───┐            │                            │
│    │ C │────▶│ D │            │  执行日志:                 │
│    └───┘     └───┘            │  [10:30:15] 开始执行       │
│                                │  [10:30:45] 工具调用成功   │
│                                │  [10:31:20] 等待审批       │
│                                │                            │
├────────────────────────────────┴────────────────────────────┤
│                      实时日志流                              │
└─────────────────────────────────────────────────────────────┘
```

**核心组件：**

| 组件 | 说明 |
|------|------|
| 任务列表 | 支持按状态/时间/模型过滤，支持批量操作 |
| DAG 可视化 | 基于 React Flow 的交互式图可视化 |
| 任务详情面板 | 展示任务元数据、执行日志、Token 消耗 |
| 实时日志流 | 底部区域，实时滚动显示系统日志 |

**DAG 节点设计：**

```
┌─────────────────────────┐
│  ● 节点名称              │  ← 状态指示灯（绿/黄/红/灰）
│  Agent: CodeAgent       │  ← 执行 Agent
│  模型: claude-sonnet     │  ← 使用模型
│  Token: 523             │  ← Token 消耗
│  耗时: 12s              │  ← 执行时间
└─────────────────────────┘
```

**交互细节：**

- DAG 节点支持点击展开详情
- 支持缩放、平移、自动布局
- 节点状态实时更新（动画效果）
- 支持暂停/恢复/取消任务
- 支持断点续传（从失败节点重新开始）

## 5. 交互流程

### 5.1 对话流程

```
用户输入消息
    │
    ▼
前端发送到后端 API
    │
    ▼
后端创建任务，返回任务 ID
    │
    ▼
前端建立 WebSocket 连接
    │
    ▼
后端流式推送消息
    ├─ Agent 思考过程
    ├─ 工具调用请求
    ├─ 工具执行结果
    └─ 最终回复
    │
    ▼
前端实时渲染
    ├─ 显示思考过程（可折叠）
    ├─ 显示工具调用卡片
    └─ 显示最终回复
    │
    ▼
用户可选择：
    ├─ 继续对话
    ├─ 重试消息
    ├─ 编辑消息
    └─ 分支对话
```

### 5.2 任务执行流程

```
任务创建
    │
    ▼
DAG 生成（可视化）
    │
    ▼
节点执行
    ├─ Agent 选择
    ├─ 模型选择
    ├─ 工具调用
    └─ 结果返回
    │
    ▼
状态更新（实时）
    ├─ 节点颜色变化
    ├─ 进度条更新
    └─ 日志滚动
    │
    ▼
任务完成/失败
    ├─ 成功：显示结果摘要
    └─ 失败：显示错误详情 + 重试选项
```

### 5.3 模型配置流程

```
点击"添加模型"
    │
    ▼
选择供应商（Anthropic/OpenAI/Ollama/自定义）
    │
    ▼
填写配置
    ├─ API Key
    ├─ Base URL（可选）
    └─ 模型参数
    │
    ▼
测试连接
    ├─ 成功：显示绿色对勾
    └─ 失败：显示错误信息
    │
    ▼
保存配置
    │
    ▼
配置任务绑定策略
    ├─ 代码生成 → 模型 A
    ├─ 简单问答 → 模型 B
    └─ 复杂推理 → 模型 C
```

## 9. API 接口设计

### 9.1 对话接口

```typescript
// 创建会话
POST /api/sessions
Body: { title?: string }
Response: { session_id: string }

// 发送消息
POST /api/sessions/{session_id}/messages
Body: { content: string, attachments?: File[] }
Response: { message_id: string }

// 获取消息流（SSE）
GET /api/sessions/{session_id}/messages/{message_id}/stream
Response: Server-Sent Events

// 获取历史消息
GET /api/sessions/{session_id}/messages
Query: { limit?: number, offset?: number }
Response: { messages: Message[] }
```

### 9.2 任务接口

```typescript
// 获取任务列表
GET /api/tasks
Query: { status?: string, limit?: number, offset?: number }
Response: { tasks: Task[] }

// 获取任务详情
GET /api/tasks/{task_id}
Response: Task

// 获取任务 DAG
GET /api/tasks/{task_id}/dag
Response: DAG

// 暂停/恢复/取消任务
POST /api/tasks/{task_id}/pause
POST /api/tasks/{task_id}/resume
POST /api/tasks/{task_id}/cancel
```

### 9.3 模型接口

```typescript
// 获取模型列表
GET /api/models
Response: { models: ModelConfig[] }

// 添加模型
POST /api/models
Body: ModelConfig
Response: { model_id: string }

// 更新模型
PUT /api/models/{model_id}
Body: Partial<ModelConfig>
Response: ModelConfig

// 删除模型
DELETE /api/models/{model_id}

// 测试连接
POST /api/models/{model_id}/test
Response: { success: boolean, latency_ms: number }

// 获取模型绑定策略
GET /api/models/bindings
Response: { bindings: TaskModelBinding[] }

// 更新模型绑定策略
PUT /api/models/bindings
Body: { bindings: TaskModelBinding[] }
```

### 9.4 记忆接口

```typescript
// 搜索记忆
GET /api/memory/search
Query: { query: string, top_k?: number }
Response: { memories: Memory[] }

// 获取记忆列表
GET /api/memory
Query: { type?: string, limit?: number, offset?: number }
Response: { memories: Memory[], total: number }

// 获取记忆详情
GET /api/memory/{memory_id}
Response: Memory

// 更新记忆
PUT /api/memory/{memory_id}
Body: Partial<Memory>
Response: Memory

// 删除记忆
DELETE /api/memory/{memory_id}
```
