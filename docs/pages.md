# Symbio 页面手册

这份文档回答三个问题，对每一个页面都回答一遍：

- **它是什么** —— 这一页在界面上提供什么能力。
- **为什么存在** —— 它服务于 Symbio 的哪个主张。如果一个页面回答不了这个问题，它就该被删掉，而不是被美化。
- **怎么用** —— 你实际会在什么时刻打开它，按什么顺序操作，看到什么算正常。

> 关于文档定位：本文档是页面层面的唯一说明书（早期的 `docs/ui-design.md` 描述的是顶部导航布局，与现状不符，已删除）。视觉层面的规则见根目录 `DESIGN.md`。能力的实现程度以 `src/symbio/capabilities.py` 为唯一真源，不以任何文档的描述为准。

## 全局约定

**导航结构。** 左侧栏 6 个分组，共 18 个入口——每个页面都有入口，没有只能靠改 URL 才能到达的页面。

| 分组 | 页面 | 这一组回答的问题 |
| --- | --- | --- |
| 核心 | 对话 | 我怎么用它？ |
| 智能体 | 任务监控、人工审批、Agent 工作台、A2A 协议、微信机器人、外部 Agent | 它自己在干什么？我怎么介入？ |
| 工具 | Skills 管理、沙箱执行、MCP 工具网关、安全防火墙、Computer Use | 它有什么手脚？边界在哪？ |
| 知识 | 记忆管理、本体图谱 | 它记住了什么？ |
| 分析 | 仪表盘、能力账本、数据飞轮 | 它值不值这个钱？它有没有在变强？ |
| 配置 | 模型配置 | 我怎么调它？ |

分组顺序是有意的：**从"我操作它"走到"它自己跑"，再走到"我核对它"**。越靠上的越日常，越靠下的越周期性。

**通用交互。** `Ctrl/Cmd + K` 打开命令面板搜索页面；分组标题可折叠，状态写入 localStorage；右上角主题按钮在浅色/深色间切换，未手动切换过时跟随系统 `prefers-color-scheme`。

**读页面的三个信号。**

- 徽章/状态点的颜色只有五种含义：绿=通过、红=失败、黄=等待或降级、青=提示、紫=追踪链路。
- 等宽字体只出现在"可以逐位核对的量"上：token 数、金额、耗时、哈希、ID。看到等宽就意味着这个数字是可对账的。
- 灰色装饰文字（分隔符、水印）不承载任何你需要读到的信息。如果一条信息只用灰色说，那是缺陷，不是设计。

## 核心

### 对话（`chat`）

**它是什么。** 与 Symbio 交互的主入口。左侧是会话列表，中间是消息流，输入框上方是模型/模式选择。回答过程中的工具调用、检索命中、成本消耗会以行内轨迹的形式展开。

**为什么存在。** 这是唯一一个"不需要理解 Symbio 架构就能用"的页面，也是所有其他页面的数据来源——没有对话，就没有 token 消耗、没有记忆、没有失败样本、没有可分析的东西。它同时承担演示职责：一个陌生人打开 Symbio，第一眼看到的就是这里。

**怎么用。**

1. 选模型与模式，输入问题，回车发送。
2. 回答期间关注行内轨迹：调了哪个工具、命中了哪条记忆、花了多少 token。这是 Symbio 与普通聊天框的区别所在——过程是可见的。
3. 如果触发了需要人工确认的动作，这里会提示，实际审批在 **人工审批** 页完成。
4. 会话自动保存，可在左侧列表回溯。

**什么算正常。** 首次打开无会话时应看到引导而非空白。轨迹区域没有内容不代表出错——简单问题本来就不需要调工具。

## 智能体

### 任务监控（`tasks`）

**它是什么。** 后台任务的运行视图：正在跑什么、跑到哪一步、耗了多久、结果是什么。

**为什么存在。** Symbio 的价值在于能自己跑一段时间，而"能自己跑"的前提是**跑的时候你看得见**。一个没有任务视图的 Agent 系统，在出问题时只能靠翻日志。这一页把"它在干什么"从日志级别提升到界面级别。

**怎么用。** 派出长任务后打开这里；观察状态流转；卡住或异常时从这里定位到具体步骤，再去 **沙箱执行** 或 **安全防火墙** 看是不是被拦了。

### 人工审批（`hitl`）

**它是什么。** Human-in-the-loop 的审批队列。Agent 想执行高风险动作时在这里排队，等你放行、驳回或修改。

**为什么存在。** 这是 Symbio 敢于给 Agent 真实权限的前提。**审批不是限制自动化，而是自动化的许可证**——正因为有一道人工闸门，才可以放心把写文件、跑命令、调外部服务的能力交出去。这一页存在的意义是让"授权"变成一个具体的、有记录的动作，而不是一个开关。

**怎么用。**

1. 收到待审提示后打开这里。
2. 逐条看清楚：谁请求的、要做什么、影响范围。
3. 放行 / 驳回。驳回时说明原因——这条原因会进入失败样本，被 **数据飞轮** 用于改进。

**注意。** 审批总开关在 **模型配置** 页。关掉它意味着 Agent 的高风险动作不再询问，请明确知道自己在做什么。

### Agent 工作台（`workbench`）

**它是什么。** 多开平铺的 Agent 操作台：同时开多个会话窗格、进交互终端、接管正在运行的会话。

**为什么存在。** 对话页是"一问一答"，工作台是"同时盯几件事"。当你从"试用 Symbio"进入"用 Symbio 干活"，就会需要并行——一个窗格跑重构，一个窗格查文档，一个终端手动介入。这一页是单人开发者的多路复用器。

**怎么用。** 新建窗格 → 分配任务 → 平铺观察 → 需要手动干预时直接在对应窗格接管。

### A2A 协议（`a2a`）

**它是什么。** Agent-to-Agent 协议的对接面：暴露自己的 Agent Card、发现对端、发起跨 Agent 调用。

**为什么存在。** Symbio 不假设自己是唯一的 Agent。A2A 让它能被别的系统当作一个能力提供方调用，也能反过来调用别人。这一页的意义是**把 Symbio 从一个应用变成一个可组合的节点**。

**怎么用。** 查看/校验本机 Agent Card → 添加对端地址 → 发起一次调用验证连通性 → 之后由 Agent 在任务中自行使用。

### 微信机器人（`wechat`）

**它是什么。** 把 Symbio 接到微信上：扫码登录、消息路由、会话映射。

**为什么存在。** 这是"随身可用"的通道。前面所有页面都要求你坐在电脑前打开浏览器，而微信意味着在通勤路上也能派活。它证明 Symbio 的入口不绑定在这个 Web UI 上。

**怎么用。** 打开页面 → 扫码 → 确认在线状态 → 在微信里直接对话，会话会同步回 **对话** 页。

**注意。** 二维码区域初始为空是正常的——它在你点击开始登录后才由前端填充。

---

### 外部 Agent（`external-agents`）

**它是什么。** 接管本机上其他 CLI Agent（Codex、Claude Code 等）的会话：列出可用的 Agent、起一个受控会话、往里发指令、看它逐轮的输出和退出码，也可以让两个 Agent 互相接力（relay）。对应能力账本的 `external_agent_control`。

**为什么存在。** 前面的页面都是"Symbio 自己动手"。这一页承认一件事：有些活别的 Agent 更擅长，或者你本来就在用它们。与其重写一遍它们的能力，不如把它们当成可调度的执行器——Symbio 负责编排和留痕，具体活让谁干是可选的。这也是"Symbio 是基础设施，不是又一个聊天框"这个主张最直接的证据。

**怎么用。**

1. 先看 Agent 列表：哪些在本机可用（装了对应 CLI 才会出现）。
2. 起一个会话，或用「接管」附到一个已存在的会话上。
3. 往里发指令，观察每一轮的输出、退出码、耗时。退出码不是 0 就是这一轮失败了，卡片会标出来。
4. 需要两个 Agent 交替处理时用接力模式，每一轮属于谁、说了什么都按顺序记下来。

**注意。** 这一页驱动的是本机真实进程，不是模拟。发出去的指令会真的在你的机器上执行，输出也是真实回显。

## 工具

### Skills 管理（`skills`）

**它是什么。** Skill 的清单与开关：有哪些技能、各自做什么、启用与否。

**为什么存在。** Skill 是 Symbio 能力的可插拔单元。这一页让"它会做什么"变成一份可以逐条读完的清单，而不是散落在代码里的隐性行为。**能力必须可清点**，这是本项目的一贯立场。

**怎么用。** 浏览清单 → 读明白每个 Skill 的触发条件 → 按需启停。

### 沙箱执行（`sandbox`）

**它是什么。** 代码执行的隔离环境与执行记录：跑什么、在什么限制下跑、输出是什么。

**为什么存在。** Agent 要写代码就得跑代码，跑代码就有风险。沙箱是"允许它动手"的技术前提，而这一页是沙箱的可观测面——**限制本身必须是可见的**，否则你无法判断一次执行到底安全在哪。

**怎么用。** 查看资源与权限限制 → 提交执行或查看 Agent 的历史执行 → 对照输出与退出码定位问题。

### MCP 工具网关（`mcp`）

**它是什么。** Model Context Protocol 的工具接入面：连了哪些 MCP Server、暴露了哪些工具、健康状况如何。

**为什么存在。** MCP 是 Symbio 获取外部能力的标准通道。这一页存在的意义是让工具接入**不需要改代码**——加一个 Server 就多一批能力，且能立刻在界面上确认它是否真的可用。

**怎么用。** 添加 Server → 确认工具列表被正确发现 → 在对话或任务中使用 → 出问题时回这里看健康状态。

### 安全防火墙（`security`）

**它是什么。** 提示注入与危险操作的拦截视图，以及审计记录。

**为什么存在。** Symbio 会读取网页、文件、外部 Agent 的返回，这些都是不可信输入。防火墙是防线，而这一页是防线的账本——**拦了什么必须留痕**。`benchmarks/` 中约 65% 的注入拦截率就是在这里被验证的。

**怎么用。** 日常不需要打开；出现可疑行为时来查审计记录，定位是哪条规则拦了什么，或者该拦没拦。

### Computer Use（`computer-use`）

**它是什么。** 让 Agent 直接操作图形界面：截屏、点击、输入。

**为什么存在。** 有些事没有 API，只有界面。Computer Use 是最后手段，也是能力边界的最外圈。它存在的意义是承认"不是所有系统都可编程"，同时把这种高风险能力**收在一个明确的页面里**，而不是混在普通工具中。

**怎么用。** 谨慎使用。确认目标窗口 → 发起操作 → 全程观察截屏反馈。这是最应该配合 **人工审批** 使用的能力。

## 知识

### 记忆管理（`memory`）

**它是什么。** 记忆条目的检索与管理：标题、正文、标签、来源、重要度、被访问次数。搜索框走语义检索（不是关键词匹配），旁边的下拉框按重要度分档筛选（高 ≥80% / 中 50–80% / 低 <50%）。

**为什么存在。** Symbio 的核心主张之一是"用检索替代重复推理"——`benchmarks/` 记录的约 85% LLM 调用规避、剪枝到 25%，靠的就是记忆命中。这一页是**主张的可验证面**：如果记忆里什么都没有，那些数字就不成立。

**怎么用。** 用完一段时间后打开，确认该记住的记住了；用搜索框验证某件事检索得到；重要度筛选用来找"被高估或低估的记忆"；错误的条目直接删。

**注意。** 筛选按的是重要度，不是"短期/长期"或"情节/语义"这类记忆类型——接口返回的记忆条目里没有类型字段，做成类型下拉框会永远筛不出东西。此前界面上确实有过这样一个下拉框，它从来没有生效过。

### 本体图谱（`ontology`）

**它是什么。** 实体与关系的图结构视图。

**为什么存在。** 记忆是条目，本体是结构。条目回答"它记得这件事吗"，本体回答"它知道这些事之间的关系吗"。后者才是把散装记忆变成可推理知识的部分。

**怎么用。** 从一个实体出发展开关系 → 检查关系是否正确 → 发现错误关联时修正。

**注意。** 缩放要按住 `Ctrl/⌘` 再滚轮——图谱占满整个视口，无条件接管滚轮会让你在图上滚不动整页。拖背景平移，拖节点重排，悬停高亮邻居。首次打开一片空白通常不是出错：结构化实体要等对话、记忆或工具执行产生之后才会形成。

## 分析

### 仪表盘（`dashboard`）

**它是什么。** 用量与成本的汇总：token 消耗、按模型分组的花费、记忆规模、趋势。

**为什么存在。** 回答"它值不值这个钱"。Symbio 的优化主张（少调 LLM、多命中缓存）如果是真的，就必须在这里看到成本曲线的形状。**没有成本视图的优化主张是空话。**

**怎么用。** 周期性打开；对比按模型的消耗分布，判断该不该换模型或调阈值。

**注意。** 首次使用无数据是正常的，发起几次对话后才会出现分组明细。

### 能力账本（`capabilities`）

**它是什么。** 21 项能力的实现状态清单，每项标注 `implemented` / `partial` / `missing`，附代码证据路径与下一步计划。当前 19 项已实现、2 项部分实现（沙箱集群、联邦隐私）。

**为什么存在。** **这是整个产品最不可复制的部分，也是最该被先看到的一页。** 任何项目都能在 README 里列一串功能，但 Symbio 把"声称"变成了运行时校验的账本：每一条声明都指向具体代码文件，且有测试断言这些路径真实存在（`tests/test_capabilities.py`）。`partial` 会如实显示为 `partial`，不会被粉饰成完成。

如果你只看一页就想判断这个项目是否诚实，看这一页。

**怎么用。** 按状态筛选 → 读 claim 与 next_step → 顺着 evidence 路径直接跳到代码验证。

**注意。** 页面顶部会显示"账本快照时间"。这一页读的是运行中服务里的账本，不是文档里的抄写本——`docs/feature-checklist.md` 之类的清单可能滞后，以这一页和 `src/symbio/capabilities.py` 为准。

### 数据飞轮（`evolution`）

**它是什么。** 失败样本 → SOP 沉淀 → 微调训练的闭环视图。

**为什么存在。** 回答"它有没有在变强"。前面所有页面描述的是**当前**能力，这一页描述的是能力的**导数**。失败被记录、被归纳成 SOP、被用于训练——这条链路是 Symbio 区别于"一个调了 API 的壳"的地方。

**怎么用。** 查看失败记录 → 归纳为 SOP → 需要时启动训练作业。

**注意。** 启动 LoRA 训练会下载模型权重并长时间占用本机资源，且目前没有取消入口。启动前请确认这是你想要的。

## 配置

### 模型配置（`models`）

**它是什么。** LLM 提供方、模型、密钥、参数，以及人工审批等运行策略的配置面。

**为什么存在。** Symbio 不绑定单一模型供应商。这一页是所有推理行为的总闸，也是唯一一个改动会立刻影响全系统行为的页面。

**怎么用。** 配置提供方与密钥 → 设默认模型 → 保存 → 回 **对话** 页验证一次。

**注意。** 这一页同时管着人工审批开关。改任何配置后请确认审批状态仍符合预期。
